# Project: Antigravity-Exclusive Editing

**Repo:** `gpocali/pi-encoder-scheduler` · **Workspace:** `/storage/antigravity/workspace/`

## When antigravity-cli skill is active in this session

ALL code changes, file edits, and git operations MUST go through Antigravity (`agy`) via the `antigravity-dev` Docker container. This is non-negotiable. Local editing causes forks — do not do it.

### What is FORBIDDEN when antigravity is active

- **No direct file writes** — never use Hermes `write_file`, `patch`, or any file-editing tool to modify project files
- **No local git operations** — never run `git add`/`commit`/`push`/`status`/`diff` via `terminal` inside the workspace
- **No local code execution that writes files** — `execute_code` must not create or modify project files
- **No reading files via Hermes tools then editing locally** — if you read a file locally, you must still route the edit through `agy`

### What IS required

- **All edits:** `docker exec -t antigravity-dev agy -p '<description of the change>' --dangerously-skip-permissions`
- **All commits:** include the commit message in the `agy` prompt, or follow up with `docker exec -t antigravity-dev agy -p 'commit the changes with message: <message>'`
- **All pushes:** route through `agy` — `docker exec -t antigravity-dev agy -p 'push to origin'`
- **All file reads for context:** can be done either via `agy` or locally (reading is fine; writing is not)

### How to detect antigravity is active

The `antigravity-cli` skill content is present in your system prompt. If you see references to `agy`, `antigravity-dev` container, `docker exec`, or the Antigravity workflow in your loaded context — antigravity mode is active. When in doubt, use `agy`.

### Rationale

Antigravity runs in an isolated container with its own git state. Local Hermes edits bypass that container, creating divergent histories (forks) that are painful to reconcile. Every change must flow through the same container to keep a single source of truth.

## When antigravity-cli skill is NOT active

Standard Hermes editing rules apply. Local `write_file`, `patch`, and `terminal` git operations are permitted.
